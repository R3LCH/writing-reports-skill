# ГУАП: LaTeX PDF и редактируемый DOCX

Для совместной сдачи DOCX/PDF предпочтителен [Word-master с отдельным титульным шаблоном](word-master.md), выбранный после практического сравнения трёх маршрутов. Этот документ сохраняет нормативную карту и инструкции альтернативного LaTeX-first маршрута, когда он явно требуется.

## Источники и область применения

Это перечень применяемых стандартов, не единая методичка для всех видов работ. Не объявлять документы действующими во всей РФ только по присутствию в подборке. Перед новой работой проверять страницу, поправки и требования кафедры; фиксировать URL, дату, пункт, применённое правило и исключения.

## Исправления относительно upstream

Основа: [latex-g7-32](https://github.com/latex-g7-32/latex-g7-32), commit `fa9f9a847c1074c0aee5895872403fb276e15a7b`, submodule G7-32 `1d9c51a8e4b38faa715ea8b3c7154bbadc8d8da1`. В README и коде остались названия старых ГОСТ 7.32–2001/2.105–95. Поэтому использовать локальный `guap-report.sty`, а не доверять названию ветки.

| Проверяемое правило | Источник | Решение профиля |
|---|---|---|
| А4, односторонняя печать; поля 30/15/20/20 мм | 7.32, 6.1.1 | Правое поле **15 мм**, вместо upstream 10 мм. Footer зарезервирован внутри нижнего поля. |

| Полуторный интервал, отступ 1,25 см | 7.32, 6.1.1 | LaTeX: 14 пт / 21 пт между базовыми линиями; DOCX: 14 пт и Word multiple 1.5. Межстрочные метрики движков различаются; проверять оба результата. |
| Структурные заголовки прописными, по центру, без номера; разделы с новой страницы | 7.32, 6.2.1–6.2.4 | `frontmatter`/`backmatter`, `chapter*`; основная часть — `mainmatter`, `chapter`, `section`. Не заменять это ручными пробелами. |
| Сквозная арабская нумерация, по центру снизу; титул учитывается, цифра скрыта | 7.32, 6.3 | LaTeX `GuapTitle`, без сброса счётчика; DOCX different-first-page и PAGE field. |
| Подпись рисунка снизу по центру, таблицы сверху слева | 7.32, 6.5.7–6.5.8, 6.6.1 | Явные настройки captions; таблицы DOCX — настоящие Word tables. |
| Оглавление с отточиями и действительными страницами | 7.32, 5.4.1 | Повторная сборка TeX; поле TOC в Word, обновляемое перед сдачей. |

Локальное окружение библиографии удерживает номера внутри поля, с абзацным отступом: upstream list hooks выводили их левее 30 мм. Кафедральная методичка и предоставленный титульный лист выше профиля. Все отклонения фиксировать с основанием, не называть изменённый профиль буквально соответствующим ГОСТ без оговорок. Профиль не воспроизводит титул НИР с госрегистрацией и грифами утверждения в студенческом отчёте.

## Воспроизводимый процесс

Пути ниже относительно корня репозитория. Каталог отчёта — приватный, новый; не помещать туда чужие персональные данные и историю других работ.

```sh
python3 skills/writing-reports-pandoc-gost/scripts/latex_report.py prepare /path/to/private-report
# Заменить демонстрационное содержание report.tex и титул на реальные исходные данные.
python3 skills/writing-reports-pandoc-gost/scripts/latex_report.py build /path/to/private-report
python3 skills/writing-reports-pandoc-gost/scripts/latex_docx.py /path/to/private-report
/usr/bin/python3 skills/writing-reports-pandoc-gost/scripts/finalize_docx.py /path/to/private-report/build/report.docx
```

Для PDF нужен XeLaTeX с пакетами класса (TeX Live с кириллицей, XeTeX, extra/рекомендуемыми LaTeX-пакетами) или Tectonic: `build ... --engine /path/to/tectonic`. Для DOCX нужны Pandoc и python-docx. Для автоматического обновления TOC и независимого рендера DOCX нужны LibreOffice Writer и Python UNO. Устанавливать зависимости до начала сборки; Tectonic прогреть на том же примере, затем использовать `--offline`. `--untrusted`/`-no-shell-escape` запрещает shell escape, но **не заменяет файловую изоляцию**: доступ сборки ограничивать только необходимыми исходниками.

Подготовка сохраняет закреплённые файлы upstream и их GPL-лицензию рядом с исходником; локальные изменения — в `guap-report.sty`. При передаче изменённых upstream-файлов соблюдать их лицензию. Шрифт Times New Roman использовать из законно установленного источника; скрипт не распространяет шрифты Microsoft.

## Контракт общего исходника

`report.tex` — общий содержательный источник; не PDF как вход DOCX. Использовать семантические `chapter`/`section`, обычные абзацы, `tabular`/`longtable`, `includegraphics`, математические окружения и явные labels. Титул заключать в `GuapTitle`; placeholder в квадратных скобках оборачивать в `{...}`, чтобы LaTeX-reader не принял его за optional argument. Структурные разделы задавать `chapter*` + `addcontentsline` для TeX TOC. Текст из DOCX/XLSX читать и сверять с исходниками до вставки в TeX.

Экспорт DOCX поддерживает заголовки, native tables/рисунки, формулы OMML, нумерацию обычных `equation`, ссылки на разделы/таблицы/рисунки/формулы и простую библиографию `bibitem{key}`/`cite{key}`. Не маскировать потери сложных макросов: raw TeX, неизвестные ссылки и предупреждения Pandoc останавливают экспорт. Нестандартные окружения, приложения, многостраничные таблицы, рисунки PDF/SVG и сложные титулы проверять и при необходимости переводить в совместимое семантическое представление либо строить DOCX непосредственно из тех же данных. Формулы Word сохранять редактируемыми; их нумерацию проверять отдельно. Pandoc не является обязательным путём для всех отчётов: при неподдерживаемой семантике использовать native DOCX, не отдавать испорченную конверсию.

Наличие `.docx` не означает готовность: `finalize_docx.py` обновляет оглавление/поля, сохраняет DOCX и создаёт `report-word-layout.pdf`. Это **рендер DOCX**, не замена `report.pdf`, собранного LaTeX. Финализатор записывает checksum окончательного DOCX и независимого PDF в `docx-manifest.json`; после дальнейших изменений повторять финализацию. Если UNO нет, обновить все поля в Word/LibreOffice вручную, сохранить, пересчитать checksum и проверить экспорт; не сдавать пустое или устаревшее оглавление.

## Нормоконтроль перед сдачей

1. Собрать TeX до стабилизации ссылок/TOC; устранить missing glyphs, undefined refs, overfull boxes. Подключённые рисунки и таблицы должны помещаться в 165 мм ширины текста.
2. Обновить Word TOC; проверить действительные страницы, отсутствие пустого листа после титула/оглавления и скрытый номер на титуле.
3. Растеризовать **каждую страницу обоих PDF** и просмотреть титул, оглавление, длинные заголовки/таблицы, рисунки, формулы, список источников, приложения. Проверить переносы, обрезание, отрывы подписей, нечитаемые надписи и нежелательные цвета.
4. В PDF проверить А4, встроенные шрифты и геометрию; в DOCX — section margins, effective styles, native tables, PAGE/TOC fields, OMML. Сборка и XML-анализ не заменяют просмотр страниц.
5. Сверить содержание обоих результатов с источниками и расчётами. Пагинация PDF и DOCX может различаться; содержание, значения, подписи и ссылки — нет.
6. Отдать оба запрошенных файла, `.tex`, профиль, изображения, расчёты, template-lock, build logs и manifest применённых правил/проверок. Не обещать «идеальный отчёт»: перечислить реально выполненные проверки и оставшиеся ограничения.
